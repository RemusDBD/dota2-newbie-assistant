# 赛后数据复盘

本模式根据比赛 ID 和指定英雄分析 OpenDota 返回的基础数据与结构化时间线。它不是录像复盘：不下载 `.dem`、不播放视频、不切帧，也不评价鼠标、镜头或无法从数据确认的瞬时走位。

## 输入与查询

最少输入：`比赛 ID + 英雄名称`。英雄可以属于用户，也可以属于该局其他玩家；不要要求 Steam 账号或假设英雄归属。

在 Skill 根目录运行：

```powershell
& "scripts\get-match-review-data.ps1" -MatchId 8461956309 -HeroName "主宰"
```

也可以传 OpenDota 英雄 ID：

```powershell
& "scripts\get-match-review-data.ps1" -MatchId 8461956309 -HeroId 8
```

脚本接受 Valve 简体中文正式名称、英文名称、内部名称和少量常见简称。语音简称先按 [voice-aliases.md](voice-aliases.md) 归一化。脚本报英雄不在该局时，使用错误信息中的十名英雄候选进行一次最短澄清。

## 数据完整度

先读取脚本输出的 `dataStatus`：

- `parsed`：至少有购买记录或分钟经济时间线，可以做完整数据复盘。
- `basic`：只有结算字段；可以评价胜负、KDA、最终正反补、GPM、XPM、英雄伤害和最终装备，但不能编造购买时间、10分钟表现或经济拐点。

继续检查 `availability`。任何章节需要的字段为 `false` 时，直接说明“该局未返回此项解析数据”，不要用常识补数值。OpenDota 已解析也不保证每场都有完整团战、视野或目标事件。

## 证据层级

复盘中的句子分为两类：

- **数据事实**：脚本直接返回的数值、时间和事件，例如“10分钟经济3120”“14:08购买推推棒”“22:41团队经济从领先转为落后”。
- **复盘判断**：基于多个事实作出的解释，例如“第一件保命装偏晚，使中期容错降低”。判断要使用“主要问题、可能错过、较大概率”等适度措辞，不能写成唯一因果。

以下内容没有位置轨迹时不得写成事实：玩家正在某一路刷钱、传送是否可用、具体站位、技能是否按慢、为什么没有参团。`teamfights` 没有记录目标英雄贡献时，只能说明解析记录未显示贡献，并结合其他数据谨慎判断。

## 阶段分析

阶段时间是复盘约定，不是固定游戏规则：

- **对线期**：默认0～10分钟。看5/10分钟经济、经验、正反补、队内和全场经济排名，以及第一批补给和小件。
- **中期**：默认10～25分钟。看第一件关键装、经济增长是否停滞、团战贡献、建筑/肉山事件和团队经济方向。
- **后期**：默认25分钟以后。看关键装备是否补齐、死亡与买活、团战生存、核心伤害或辅助功能，以及领先能否兑现。

比赛很短时按实际目标事件调整。例如18分钟结束的比赛，可以把12分钟后称为“终结阶段”，不要机械生成不存在的大后期。

## 对线评价

优先使用 `economyTimeline` 的5分钟和10分钟节点，再结合 `lineup[].minute10`：

1. 核心位重点看经济、补刀、等级/经验与同队经济排序；反补只作为兵线控制信号之一。
2. 辅助位不能用补刀数直接判低分，重点看等级、死亡、参战、真假眼、叠野以及第一件功能装时间。
3. `lane` 或 `laneRole` 缺失时，不自行指定对线英雄；只能和全场、队内或用户明确提供的对手比较。
4. 最终正补不能反推10分钟补刀；没有 `lh_t` 就不评价具体对线补刀表现。

## 经济与出装

- 用 `purchaseTimeline` 还原真实购买顺序。消耗品和配件可以归入阶段描述，但不要删除会影响判断的魔棒、鞋、真假眼、粉、雾和保命小件。
- 用 `economyTimeline` 找增长变慢、死亡后停滞或团战获利的区间；不要仅凭最终 GPM 推断整局稳定性。
- 出装评价必须结合英雄位置与敌方威胁。热门路线只能作为旁证，不能覆盖本局实际需求。
- 当目标英雄是别人时仍按该英雄本局职责复盘，不使用“你当时”假设操作者身份；可以写“该英雄/这名玩家”。

## 关键时间点

最多选三个，优先级如下：

1. 团队经济或经验优势发生明显反转。
2. 一场有多人死亡、买活或显著金钱变化的团战。
3. 肉山、高地、兵营或关键塔事件。
4. 核心装备完成后立刻打赢/打输，或长时间没有形成下一件有效装备。

每个节点使用：`时间｜数据事实｜复盘判断`。如果只有分钟级时间线，显示整分钟并说明是分钟快照，不伪造秒数。

## 胜负点评价

避免“某一件装备导致输掉比赛”这类单因果结论。应先指出可验证的比赛走向，再解释最可能影响结果的2～3个因素，例如：

- 对线领先是否转化为塔、肉山或敌方野区控制。
- 核心经济是否在中期关键窗口停滞。
- 辅助功能装是否在对方强势期前完成。
- 关键团战中的伤害、治疗、死亡和买活是否符合英雄职责。

结尾只给三条下一局可执行规则。规则要能由玩家看到触发条件后立即行动，例如“核心能独立站线且墓碑转好时，跟先手位开雾”，而不是“提高意识”。

## 失败与降级

- OpenDota 查询失败、限流或超时：报告错误并停止，不反复请求。
- 比赛 ID 存在但尚未解析：输出基础结算复盘，不自动提交外部解析任务。
- 英雄不在该局：列出脚本返回的候选英雄，等待用户纠正名称。
- 数据互相矛盾或字段异常：保留原始事实并降低结论强度，不自行修正数据。
